# ADR-002 - Hybrid Detection with Safe Syntax Probes

## Status

Accepted

## Context

W1 的特征评分能区分三个基础样例，但短片段、混合语法和共享符号可能碰撞。正式系统需要提高 C++/Python 判断可信度，同时遵守“永不执行用户代码”的安全边界。

## Alternatives

1. 只使用关键词与结构特征评分。
2. 直接编译并运行 C++、直接运行 Python，以运行结果判断语言。
3. 使用独立第三方解析服务或在线编译服务。
4. 特征评分后，使用本地 Python AST 与 C++ syntax-only 探针辅助决策。

## Rejected Options

- 拒绝只用特征评分：W1 三样例不足以证明混合和非标准输入的鲁棒性。
- 拒绝执行代码：它违反安全边界，并引入文件、进程和网络副作用。
- 拒绝在线解析服务：增加隐私泄露、网络依赖和不可控成本，不适合本地课程交付。

## Decision

采用混合检测。先复用可解释特征评分；最高分至少为 `5` 且分差至少为 `3` 时形成强候选，再使用本地安全语法探针辅助决策：Python 使用 `ast.parse`；C++ 使用参数数组调用 `g++ -x c++ -fsyntax-only`，在临时目录中运行并设置 3 秒墙钟超时。若本机存在 `prlimit`，再限制 512 MiB 地址空间、4 秒 CPU、1 MiB 文件输出和 64 个文件描述符。系统不生成或运行可执行文件。语法失败不能单独否定强候选，因为待诊断代码本来就可能存在语法错误；此时降低可信度并路由到对应 Analyzer。没有强候选且探针冲突、工具失败或证据不足时返回 `unknown`。

## Consequences

- 好处：保留可解释证据，同时比纯关键词更能识别语法边界；无需发送代码到外部服务。
- 代价：结果受本地 g++ 版本影响；强候选与语法结果不一致时，需要把两类证据和降低后的可信度一起暴露，不能伪装为完全确定。
- 测试要求：至少 20 个 C++、Python、模糊或混合受控样例；覆盖工具缺失、超时、语法失败和冲突结果。
- 安全要求：不使用 `shell=True`，代码不进入命令字符串，不保留临时产物。

## Rollback

如果目标环境缺少 g++，系统保留 Python AST 与特征评分，并把 C++ 可信度上限降低；证据不足时返回 `unknown`。不得用“临时执行代码”替代 syntax-only 探针。恢复 C++ 探针时必须重新运行受控语料评估。
